# Contributing

Contributions are welcome for UI fidelity, compatibility reports, accessibility, tests and documentation.

## Before opening a pull request

1. Open an issue with the expected behavior and the affected R36S/firmware variant if relevant.
2. Keep UI changes functional without external services or network permissions.
3. Do not commit ROMs, BIOS, firmware images, copyrighted box art, private keys or device backups.
4. Run `npm test` and describe the manual browser tests performed.
5. For theme compatibility changes, include the firmware fork, version, display resolution and results from a real device.

## Pull requests

Prefer small changes with a clear scope. Explain any changes to the XML generation format and supply a reproducible test case.

## Security reports

Do not publicly post private data, credentials, or exploit samples containing user data. Report security issues through GitHub's private vulnerability reporting feature when available.
